# 광고 노출 위치에 스플래시·팝업 추가 (백엔드 요청)

| | |
|---|---|
| 상태 | 초안 |
| 작성자 | 홍비 |
| 리뷰어 | (지정 필요) |
| 관련 | [광고판 (자체 광고 슬롯)](../ad-slots/spec.md) |
| 백엔드 | `nar-back-repo` — `Ad.java`, `MobileAdController` |
| 앱 | `warding-mobile-repo` — `components/cheer_ad_banner.dart` |

## 요약

백오피스 광고(`/api/ads`)의 노출 위치에 **`splash`, `popup` 두 개를 추가**해달라는 요청이다.
앱은 이미 다섯 자리 모두에 광고를 띄울 준비가 되어 있는데, 서버가 세 자리만 허용해서
스플래시·팝업 광고는 **등록 자체가 안 된다**.

## 문제

`CheerAdScreen`(응원 광고 신청 화면)은 광고 상품을 **세 개** 판다.

| 상품 | 가격(오픈 특가) |
|---|---|
| 배너 (1일) | 2만 |
| 팝업 (1일) | 4만 |
| 스플래시 (1일) | 6만 |

그런데 백오피스에서 등록할 수 있는 자리는 배너 계열 셋뿐이다.

```java
// nar-back-repo  domain/ad/entity/Ad.java
public static final Set<String> PLACEMENTS = Set.of("home", "match_list", "match_detail");
```

`Ad.update()` 가 이 Set 에 없는 값을 받으면 예외를 던진다.

```
IllegalArgumentException: 알 수 없는 노출 위치: splash
```

즉 **스플래시·팝업은 팔고 있지만 앱에 띄울 방법이 없다.** 광고주가 6만 원짜리 스플래시를
사도 운영이 등록할 수 없는 상태다.

## 요청 사항

### 1. `PLACEMENTS` 에 두 값 추가

```java
public static final Set<String> PLACEMENTS =
        Set.of("home", "match_list", "match_detail", "splash", "popup");
```

### 2. `MobileAdController` 설명 갱신

`@Operation(description = ...)` 의 `placement(home|match_list|match_detail)` 를
다섯 개로 고친다. 응답 스펙·필드는 그대로다.

### 3. 테스트

`AdTest` 에 `splash`·`popup` 이 허용되는지, 모르는 값은 여전히 거절되는지 케이스를 더한다.

### DB 는 건드리지 않아도 된다

`placement` 가 `VARCHAR(20)` 이라 값만 늘면 된다. 마이그레이션 불필요.
(`V94__Create_ad.sql` 그대로)

## 앱 쪽 (이미 반영)

앱은 다섯 자리 모두 `GET /api/ads` 를 보고, 해당 `placement` 에 노출 중인 광고가 있으면
그 이미지를, 없으면 기존 '와딩 광고 신청' 모집 배너를 둔다. **서버가 안 바뀌어도 앱은
안전하다** — 빈 목록이 오면 지금과 똑같이 모집 배너가 나온다. 서버에 두 값이 추가되는
순간 자동으로 동작한다.

| placement | 앱 자리 | 비율 |
|---|---|---|
| `home` | 홈 순위표 아래 | 960×300 |
| `match_list` | 경기 리스트 날짜 사이 | 960×300 |
| `match_detail` | 경기 상세 | 960×300 |
| `splash` | 앱 시작 스플래시 하단 | 1080×720 |
| `popup` | 홈 진입 팝업 | 1080×1440 |

## 결정

- 2026-10-13 (홍비) **placement 키는 앱 상품명과 같은 `splash`·`popup` 을 쓴다.**
  근거: 기존 셋이 앱 자리 이름을 그대로 쓰고 있어 일관된다.
- 2026-10-13 (홍비) **앱을 먼저 붙이고 서버는 뒤따른다.** 근거: 광고가 없으면 모집 배너로
  대체되므로 순서에 상관없이 안전하다.

## 미결

- 스플래시·팝업 광고의 **노출 빈도 상한**. 배너는 화면에 들어오면 매번 보이지만, 팝업은
  하루 한 번(사용자가 '오늘 하루 보지 않기' 를 누르면 그날 안 뜸) 규칙이 이미 있다.
  스플래시는 앱을 켤 때마다 뜬다 — 하루 상한이 필요한지.
- 같은 자리에 광고가 여러 건이면 지금은 `sortOrder` 첫 건만 쓴다. 로테이션이 필요한지.
- 소재 규격 확정. 현재 앱 비율은 배너 960×300 / 스플래시 1080×720 / 팝업 1080×1440 이다.
  다만 iPhone 16 Pro Max 기준 배너 렌더 폭이 1210px 라 960 소재는 1.26배로 확대된다.
  **권장 규격을 1.5배(배너 1440×450)로 올릴지** 디자인 확인이 필요하다. 비율이 같아서
  앱 코드는 바뀌지 않는다.
- 스플래시 광고가 앱 시작을 가리는 시간. 현재 스플래시 대기는 3.5초 고정이다.
