결정과 미결은 이 파일에만 적는다. 이 문서는 **어느 화면의 어디에 광고를 넣을지**만 다룬다. 광고주 모집, 가격, 결제(계좌이체·세금계산서)는 다루지 않는다. 기준 코드는 모바일 `origin/main`(2026-09-30, `d79a049`)이다.

## 목적

구글 애드 같은 외부 광고망이 아니라, 와딩이 직접 광고판을 운영하고 광고주를 모아 판다. 그러려면 먼저 화면마다 "넣어도 되는 곳 / 조건부 / 넣지 말 곳"을 정해야 한다. 잘못 넣으면 광고 수입보다 이탈이 더 크기 때문이다.

앱의 핵심 가치는 "지금 내 선수가 뭐 하고 있나"를 알려주는 것이다. 라이브 경기, 솔랭 상태, 알림은 광고가 끼어들면 안 되는 신뢰 구간이다.

## 현재 앱 구조 (광고 위치를 정할 때 알아야 할 것)

- 하단 탭이 5개다: 경기일정 · 경기리스트 · 커뮤니티 · 마이 구독 · 마이페이지. **탭 셸이 없다.** 탭마다 화면이 따로 있고, 탭을 옮길 때 `pushReplacement`(`util/tab_route.dart`)로 화면을 새로 만든다.
- 앱을 열면 첫 화면은 **경기일정(캘린더)** 이다. `HomeScreen`은 지금 로그아웃 버튼만 있는 placeholder이고, [홈 개편](../home/spec.md)이 머지되면 첫 화면이 홈으로 바뀐다.
- 진입 팝업은 이미 하나 있다. `maybeShowGuidePopup`(`components/guide_popup.dart`)이 일정 화면 `initState`에서 뜨고, 위젯 딥링크로 들어오면 안 뜬다. 봤는지는 secure storage에 버전으로 저장한다.
- 공용 컴포넌트가 이미 있다: `showNarPopup`(팝업), `showAppBottomSheet`(바텀시트), `NarBanner`(그라데이션 띠배너). 일정 화면 위쪽의 공지 띠배너가 `NarBanner` + ✕ 닫기의 기존 사례다.

## 광고 슬롯

슬롯 이름은 화면이 바뀌어도 유지되게 화면 구조가 아니라 위치 의미로 짓는다.

| 슬롯 | 형태 | 어디에 |
|---|---|---|
| `entry_sheet` | 바텀시트 | 앱 진입 후 첫 화면(홈, 개편 전에는 일정) |
| `entry_popup` | 중앙 팝업 | 같은 진입 시점. 대형 캠페인 전용 |
| `home_inline` | 카드형 | 홈 순위표 섹션과 커뮤니티 섹션 사이 |
| `match_list_inline` | 카드형 | 경기리스트, 날짜 블록 사이 |
| `match_detail_footer` | 카드형 | 경기 상세 맨 아래 |
| `mypage_card` | 카드형 | 마이페이지 |
| `community_inline` | 카드형 | **보류** (아래 "커뮤니티" 참고) |

## 화면별 판단

✅ 추천 · ⚠ 조건부 · ❌ 비추

| 화면 | 판단 | 슬롯 | 이유 |
|---|---|---|---|
| 홈 (개편 후) | ✅ | `entry_sheet`, `home_inline` / ⚠ `entry_popup` | 하루 한 번 모든 사용자가 지나가는 화면이다. 인라인은 **순위표와 커뮤니티 사이**가 자연스러운 경계다. 솔랭 카드와 오늘 경기 사이는 넣지 않는다(홈의 존재 이유를 끊는다) |
| 경기일정 (지금 첫 화면) | ❌ 인라인 / ✅ 진입 슬롯 발화 지점 | `entry_*` | 캘린더가 남은 세로 공간 전체를 채우고 하단 네비가 떠 있어서 광고를 끼울 자리가 없다. 위쪽 띠배너 자리는 **공지 전용**으로 둔다. 홈 개편 전에는 여기가 진입 슬롯의 발화 지점이고, 개편 후에는 홈으로 옮긴다 |
| 경기리스트 | ⚠ | `match_list_inline` | 조회가 많은 화면이라 광고주 가치는 높다. 날짜 헤더·리그 헤더·경기 카드가 한 줄짜리 목록(`_HeaderItem`/`_LeagueHeaderItem`/`_CardItem`)이라 광고 항목을 끼우기는 쉽다. 하지만 "오늘"로 자동 스크롤하는 로직이 항목 높이를 추정하므로 **높이가 고정**이어야 하고 **오늘 이전 영역에는 넣지 않는다**. 한 번에 50건 페이지에서 최대 2개, 오늘 블록 다음 날짜부터 |
| 경기 상세 | ⚠ | `match_detail_footer` | 세션이 긴 화면이다. 섹션 5개(Champion Pick ~ Player Builds) **사이가 아니라 맨 아래** 한 곳만 쓴다. 섹션 헤더 키로 목차·스크롤 스냅 위치를 재기 때문에 사이에 끼우면 계산이 틀어질 수 있다. 경기 전 잠금 화면에서는 광고만 덩그러니 남으므로 뺀다 |
| 커뮤니티 목록 | ❌ (지금은) | ~~`community_inline`~~ | 아래 "커뮤니티" 참고 |
| 게시글 상세 | ❌ (지금은) | — | 같은 이유. 활성화되면 본문·액션 아래, 댓글 위 한 곳을 검토한다 |
| 마이 구독 | ❌ | — | 알림 카드 피드다. 내 선수 소식 사이에 광고가 섞이면 알림 자체를 못 믿게 된다 |
| 마이페이지 | ⚠ 낮은 우선순위 | `mypage_card` | 설정을 보러 온 화면이라 광고를 기대하지 않는다. 프로필·응원팀 배너 아래 카드 한 장이면 충분하다 |
| 선수 평점 | ❌ | — | 별점·한줄평을 쓰는 입력 흐름이다 |
| 공지 · 알림함 | ❌ | — | 운영 신뢰 채널이다 |
| 로그인 · 온보딩 · 탈퇴 · 설정류 | ❌ | — | 이탈과 직결되는 화면이다. 금지 |
| 푸시 · 잠금화면 라이브 액티비티 · 위젯 | ❌ | — | 서비스가 약속한 알림 채널이다. 광고를 태우면 알림을 끄는 사람이 생긴다. 금지 |

### 커뮤니티: 지금은 넣지 않는다

커뮤니티는 인피드 광고가 잘 어울리는 화면이다. 하지만 **글이 쌓여야** 성립한다. 2026-09-30 prod 집계(공개 글만):

| 지표 | 값 |
|---|---|
| 공개 글 누적 | 35건 |
| 최근 30일 | 29건 / 작성자 15명 |
| 최근 14일 | 3건 (9/23, 9/25, 9/29 각 1건) |
| 최근 14일 댓글 | 8건 |
| 활성 기기(FCM 재등록 근사) | 1일 913 / 7일 2,844 / 30일 5,934 |

이 상태에서 5번째마다 광고를 끼우면 문제가 세 가지다.

- 전체가 35건이라 목록 두어 페이지면 끝난다. 5번째마다 넣으면 스크롤 몇 번에 광고가 계속 걸려서 **광고가 콘텐츠만큼 눈에 띈다**.
- 새 글이 하루 한 건 정도라 매일 열어도 목록이 그대로다. 같은 사람이 **같은 광고를 며칠 내내** 본다. 광고주에게도 좋지 않다.
- 죽어 가는 게시판에 광고까지 붙이면 글을 쓸 이유가 더 줄어든다. 활성화를 먼저 살려야 한다.

**다시 검토할 기준**은 미결에 둔다. 그때까지 커뮤니티 목록과 글 상세에는 광고를 넣지 않는다.

## 공통 노출 규칙

진입 슬롯(시트·팝업)은 사용자가 가장 예민한 순간에 뜬다. 보수적으로 잡는다.

1. **하루(KST) 한 번, 콜드스타트당 한 번.** 둘 다 지켜야 뜬다. 탭을 옮기면 화면이 새로 만들어지므로 화면 `initState`에서 판단하면 탭마다 다시 뜬다. 앱 프로세스 단위 플래그와 날짜 저장으로 막는다.
2. **시트 또는 팝업 중 하나만.** 한 진입에서 둘 다 띄우지 않는다.
3. **사용 가이드 팝업이 우선이다.** 가이드가 뜨는 세션에서는 광고를 건너뛴다. 신규 설치 후 유예 기간도 둔다(미결).
4. **위젯·푸시 딥링크로 들어온 세션에서는 뜨지 않는다.** 가이드 팝업이 이미 같은 규칙이다.
5. **팝업은 내 경기가 LIVE일 때 뜨지 않는다.** 시트는 뜬다. 경기 시간대가 트래픽 피크라서 둘 다 막으면 광고주가 살 게 없어진다.
6. **"광고" 라벨, ✕ 닫기, "오늘 하루 안 보기"** 를 항상 둔다. 광고 소재가 앱 UI처럼 보이면 안 된다.
7. **미판매 슬롯은 접는다.** 인라인은 높이 0으로 사라지고, 진입 슬롯은 아무것도 안 띄운다. 빈 광고판이나 "광고 문의" 배너를 사용자에게 보여주지 않는다. 광고 문의 진입점은 마이페이지 하단 텍스트 한 줄로 충분하다.
8. **공지 띠배너와 섞지 않는다.** 공지는 운영 채널이다. 광고 소재를 공지 테이블·띠배너에 얹지 않는다.

### 진입 슬롯: 시트를 기본으로, 팝업은 예외로

| | 바텀시트 | 중앙 팝업 |
|---|---|---|
| 방해 정도 | 아래에서 올라오고, 바깥 탭·스와이프로 닫힌다 | 화면 중앙을 막고, 딤 70% 위에서 버튼으로만 닫힌다 |
| 노출 강제력 | 중간 | 높음 |
| 첫인상 보호 | 좋음 | 나쁨 |
| 구현 | `showAppBottomSheet` 재사용 | `showNarPopup(child:)` 재사용 |

사용자 대부분이 알림과 라이브로 앱에 들어온다. 첫 화면을 막는 팝업은 이탈 위험이 더 크다. 그래서 **기본은 바텀시트**, 팝업은 광고주가 프리미엄으로 산 대형 캠페인에만 쓰고 **월 1~2회 상한**을 둔다. 광고 효과 차이(클릭률)는 데이터가 없어서 추정이다. 운영하며 슬롯별로 재본다.

## 사용자 흐름

1. 앱을 연다. 사용 가이드를 이미 본 사용자만 광고 진입 슬롯 대상이 된다.
2. 하루 첫 진입이면 바텀시트가 올라온다. 소재를 누르면 외부 브라우저로 랜딩 페이지가 열린다. ✕ 또는 "오늘 하루 안 보기"로 닫는다.
3. 홈(또는 경기리스트)을 스크롤하면 정해진 자리에 광고 카드가 한 장 보인다.
4. 그 외 화면에서는 광고를 보지 않는다.

## 필요한 API · 데이터

기존 광고 관련 코드는 백엔드에 없다. 공지 띠배너(`GET /api/notices/promoted`)는 있지만 광고에는 쓰지 않는다. 기간·광고주·노출 집계 개념이 없고, V62 마이그레이션 주석처럼 띠배너 열람은 집계도 안 된다.

| 데이터 | 엔드포인트 | 있음 / 새로 / 확인 필요 |
|---|---|---|
| 슬롯별 노출할 광고 | `GET /api/mobile/ads?slots=entry_sheet,home_inline` | 새로 |
| 노출·클릭·닫기 기록 | `POST /api/mobile/ads/{adId}/events` | 새로 |
| 광고 등록·기간·슬롯 배정 | 백오피스(`warding-backoffice-fe`) 화면 | 새로 |
| 공지 띠배너 | `GET /api/notices/promoted` | 있음. 광고와 분리해서 그대로 둔다 |
| 이미지 저장 | Cloudinary | 있음. 업로드 흐름은 확인 필요 |
| 외부 랜딩 열기 | `url_launcher`, 이미지는 `cached_network_image` | 있음(모바일 `pubspec.yaml`) |

응답 예시(제안):

```json
{
  "ads": {
    "entry_sheet": {
      "adId": 101,
      "imageUrl": "https://res.cloudinary.com/.../ad_101.png",
      "landingUrl": "https://example.com/event",
      "advertiserName": "예시 광고주",
      "startsAt": "2026-10-10T00:00:00+09:00",
      "endsAt": "2026-10-16T23:59:59+09:00"
    },
    "home_inline": null
  }
}
```

`null`이면 슬롯을 접는다. 서버가 하루 상한이나 유예 기간을 판단하지 않는다. 그건 기기에서 한다(서버는 사용자별 상태가 없다).

노출·클릭은 와딩이 직접 집계한다. 외부 광고 SDK나 광고 ID를 쓰지 않으므로 iOS 앱 추적 투명성(ATT) 대상이 아닌 것으로 본다. 다만 앱스토어 심사 기준은 **확인 필요**.

## 결정

- 2026-09-30 (창하) **커뮤니티가 활성화되지 않았으면 인피드 광고를 넣지 않는다.** 근거: 위 활성도 집계. 다시 볼 기준은 미결.

아래는 이 문서가 처음 제안하는 안이다. 리뷰에서 확정되면 이 섹션으로 옮긴다: 진입 슬롯은 시트 기본·팝업 예외, 미판매 슬롯은 접기, 공지와 광고 분리.

## 미결

- 커뮤니티 광고를 다시 검토할 기준. 제안: 최근 4주 하루 평균 글 20건 이상(한 페이지가 하루에 채워지는 수준), 주간 작성자 50명 이상.
- 신규 설치 후 진입 슬롯 유예 기간. 제안: 3일. 근거 데이터 없음.
- 팝업 월 상한과 가격 차이(시트 대비 프리미엄).
- 소재 규격. 제안: 팝업 이미지 4:5(팝업 안쪽 폭 287 기준), 시트 375 폭 가로형, 인라인 카드 335×100. 광고주에게 나가는 규격이라 디자인 리뷰가 필요하다.
- 홈 개편이 머지되기 전에 일정 화면에서 먼저 시작할지, 홈 개편 이후로 미룰지.
- 광고 심의 기준(도박·주류·성인·경쟁 서비스 금지 등)과 승인 주체. 결제 방식과 별개로 먼저 정해야 한다.
- 경기리스트에서 광고가 "오늘" 자동 스크롤에 영향이 없는지. 구현 전에 `match_list_screen.dart`의 높이 추정 로직으로 검증해야 한다.
- 노출 빈도 상한(같은 광고를 한 사용자에게 하루 몇 번)과 광고주 리포트 항목.
- 앱스토어·플레이 심사 기준에서 앱 내 자체 광고에 별도 신고 항목이 있는지.

## 이 문서의 한계

- 커뮤니티 활성도와 활성 기기 수는 2026-09-30 prod 읽기 전용 집계다. 활성 기기는 FCM 토큰 재등록 시각 기준 근사치이고, 화면별 조회수는 없다. **광고 노출 예상치는 화면별 조회수가 없어서 계산하지 않았다.** 슬롯 가격은 첫 달 노출 로그를 보고 정한다.
- 팝업·시트의 클릭률 차이는 추정이다.
- 목업의 광고 소재와 글 제목은 모두 지어낸 예시다.
