Warding 홈 — 최종안

섹션 다섯: 구독 선수 솔랭 상태 · 오늘 경기 · 순위표(리그·롤드컵) · 커뮤니티(최신·인기) · 유튜브 쇼츠. 순위표는 한 자리에서 세 형태로 바뀐다(리그 표 / 스위스 버킷 / 토너먼트 트리). 경기·순위는 실데이터, 솔랭과 커뮤니티 글은 예시다(공개 레포라 글은 교체).

Figma 코멘트 반영 (2026-09-20~21)

홍비님 답변으로 결정된 것 넷. 각 항목이 목업 어디에 들어갔는지 적는다.

구독 전체 페이지 — 만든다눌러서 이동

창하: "구독한 사람이 많다면 스와이프로 한계가 있을 것 같은데 별도 페이지까지 생각하는 게 좋을지?" → 홍비: "별도 페이지 구현되면 좋을 것 같습니다! 100명 구독한 사람도 있으니.."

그래서 화면을 되살리고 구독 100명 기준으로 다시 그렸다. 100명이면 목록만으론 못 찾으니 검색줄과 팀별 필터를 넣었고, 상태(솔랭 중 / 오늘 경기함 / 소식 없음)로 먼저 갈라서 위에서부터 읽으면 끝나게 했다. 소식 없는 92명은 접어서 "N명 더 보기" 뒤에 둔다. 홈의 "구독 100명 전체" 를 누르면 실제로 이 화면으로 넘어가고, 좌상단 화살표로 돌아온다 — 목업에서 눌러볼 수 있다.

평점 탭 — 넣는다반영함

창하: "추가로 평점 매긴 것도 홈화면에 뜨게 할까요?" → 홍비: "넵 좋습니다!"

커뮤니티 섹션의 평점 한줄평 탭(최근순). 한줄평 본문이 주고, 그 아래 별점·대상 선수·챔피언·작성자·시간이 붙는다. 별점은 1~5 정수이고 한줄평은 150자 제한이다(LivePlayerRatingRequest 의 @Min(1) @Max(5), @Size(max=150)).

한줄평이 달린 평가만 올린다. 점수만 매긴 건 홈에 띄울 내용이 없다 — 숫자 하나는 읽을 게 없고, 목록이 전부 같은 모양이 된다. Review.comment 가 비지 않은 것만 거른다.

막힌 곳: 평점 API 가 /api/mobile/live/games/{gameId}/ratings 라 경기 하나를 지정해야 한다. 홈에 "최근순"으로 뿌리려면 최근 세트들을 가로지르는 집계 엔드포인트가 새로 필요하다.

뉴스 섹션 — 넣는다반영함

홍비: "팬들이 뉴스도 자주 본다고 해서 뉴스 섹션도 추가해 보는 건 어떠신가요??" → "기획 이야기 해봤는데 쇼츠는 호불호 갈릴 수도 있고 뉴스 보는 사람이 더 많다고 하네요!"

쇼츠를 빼지 않고 콘텐츠 한 섹션 안에 뉴스 · 쇼츠 · 평점 세 탭으로 묶었다. 기본 탭은 뉴스 — 더 많이 본다는 근거를 기본값으로 옮겼다. 호불호가 갈리는 쇼츠는 한 번 더 누르면 나온다.

막힌 곳: 목업의 뉴스 5건은 prod 실응답 그대로인데 전부 LoL 과 무관하다(배틀그라운드·디제이맥스·펄어비스). /api/community/news 는 TOP 5 고정이라 거를 여지도 없다. LoL 필터와 페이징이 붙기 전엔 홈에 내보내면 안 된다.

"전체 = 내 선수 + 내 팀" — 맞다확인

쇼츠 필터의 전체는 두 조건의 합집합이고, 정렬은 내 선수 → 내 팀 → 나머지다. 지금 목업이 그렇게 동작한다.

아직 정하지 못한 것 · 팀원에게 넘기는 목록

이 목업이 답하지 않은 것들이다. 구현 전에 하나씩 결정이 필요하다.

솔랭 카드

  • 큰 카드에 누가 먼저 오나. 목업은 "가장 최근 시작" 순이다. 핀 고정을 줄지, 준다면 몇 명까지인지 안 정했다.
  • 경기가 끝나는 순간의 전환. 스와이프 중에 한 장이 결과로 바뀌면 손가락 아래에서 카드가 바뀐다. 다음 폴링까지 미룰지, 즉시 바꿀지.
  • 결과 카드 노출 기간 — 종료 후 6시간, 또는 다음 판 시작 중 먼저 오는 쪽. 그 뒤엔 사라지는 게 아니라 조용한 상태 줄로 강등된다. 자정 컷은 쓰지 않는다 — LCK 경기가 저녁이라 프로 솔랭은 새벽에 몰리고, 자정에 끊으면 한 세션이 반으로 잘린다. 6시간은 추정값이라 player_solo_rank_game 의 연속 판 간격 p90 으로 맞춰야 한다.
  • 카드가 "언제 끝났는지" 를 말해야 한다. 우상단은 종료 시각(12분 전 종료), 경기 길이(32분)는 본문으로 내렸다. 한 줄에 같이 두면 "32분" 이 "32분 전" 으로 읽힌다.
  • 로딩·에러 상태를 안 그렸다. 첫 진입 스켈레톤, 폴링 실패 시 마지막 값 유지 여부.

쇼츠

  • 한글 별칭 테이블이 없다. Player 에 name(Faker)·real_name(이상혁)뿐이고 제목이 쓰는 "페이커" 가 없다. 컬럼을 새로 팔지, 별칭 표를 코드 상수로 둘지.
  • 재생 위치. 임베드 플레이어를 홈 안에서 바로 돌릴지, 전체화면 피드로 보낼지. 홈에서 돌리면 WebView 메모리를 상시 먹는다.
  • 쇼츠가 기본 탭에서 밀렸다. "호불호 갈린다"는 근거로 뉴스를 앞에 뒀는데, 탭 전환율을 안 보면 쇼츠가 그냥 안 보이는 기능이 된다. 초기엔 지표를 봐야 한다.
  • 매칭 정밀도 기준선. 오탐("기인"·"룰러" 같은 일반어)을 어디까지 허용할지. 제목 매칭은 55% 재현율이고 정밀도는 아직 안 쟀다.
  • "내 팀" 필터의 팀은 무엇인가 — 구독 선수들의 소속팀 합집합인지, 별도로 고른 응원팀인지. 목업은 T1 하나로 가정했다.

순위표

  • LPL·LEC·LCS 는 비어 있다. /api/standings 가 LCK 만 준다. 칩을 지울지, 데이터를 붙일지.
  • 형태 전환 기준. 목업은 손으로 누르지만 실제로는 대회 일정으로 자동이어야 한다. 스위스→토너먼트 경계 날짜를 무엇으로 판단할지.
  • 정규시즌이 끝난 뒤 플레이오프 기간에 무엇을 보여줄지 안 정했다.

뉴스 · 평점

  • 뉴스에 LoL 필터가 없다. 소스가 네이버 e스포츠 전체라 타 게임 기사가 그대로 온다. 키워드 필터를 어디에 둘지(크롤 시점 vs 조회 시점).
  • 뉴스 엔드포인트가 TOP 5 고정이다. 페이징·정렬·필터 파라미터가 없어 확장 전엔 "더보기"를 못 만든다.
  • 평점 홈 집계 엔드포인트가 없다. 지금은 gameId 단위뿐이다. 어느 범위를 "최근"으로 볼지(최근 N세트 / 오늘 / 24시간)도 안 정했다.
  • 평점이 적게 달린 경기는 평균이 출렁인다. 최소 참여 인원 기준선이 필요하다.
  • 한줄평 비율을 모른다. 점수만 매기고 글은 안 쓰는 비중이 높으면 이 탭이 늘 비어 보인다. 붙이기 전에 comment 가 있는 평가의 비율부터 재야 한다.
  • 한줄평도 유저 글이라 신고·차단 대상이다. 커뮤니티 모더레이션을 그대로 태울지 정해야 한다.

홈 전체

  • GET /api/mobile/home 한 방 응답이 아직 없다. 지금은 섹션마다 따로 부른다. 묶을지, 섹션별 로딩을 허용할지.
  • 섹션 순서를 유저가 바꿀 수 있나. 콘텐츠 섹션이 항상 맨 아래다.
  • 탭 묶음 기준 — 밖에서 온 것(뉴스·쇼츠) / 유저가 쓴 것(글·한줄평)으로 갈랐다. 다른 기준(읽기 vs 보기)도 가능하니 확정 전에 한 번 더 본다.
  • 구독 0명인 사람의 홈. 목업은 히어로만 빈 카드인데, 쇼츠 "내 선수" 필터도 같이 비어야 맞는지.
  • 접근성 — 스와이프만으로 넘기는 카드에 키보드·보이스오버 대안이 없다.

이 목업의 한계

  • 솔랭 값(경과 시간·KDA·LP)과 평점은 지어낸 예시다. 경기·순위·쇼츠·뉴스는 prod 실데이터. 커뮤니티 글은 공개 레포라 예시로 바꿨다.
  • 선수 이미지 12명·챔피언 스플래시 4종만 넣었다. 실제로는 playerImageUrl·championLoadingImageUrl 로 받는다.
  • 칩·펼침·스와이프만 동작하고 나머지 버튼은 그림이다.
  • iPhone 375px 한 폭만 봤다. 태블릿·작은 안드로이드는 안 봤다.
