결정과 미결은 이 파일에만 적는다. 홈 화면 안에서의 위치는 [홈 spec](../home/spec.md)을 따르고, 응원에 관한 결정은 이 파일이 원천이다.

## 목적

지금 서비스는 선수의 솔랭을 알려주기만 한다. 선수 개인 팬이 "내 선수가 지금 뛰고 있다"를 알고도 할 수 있는 일이 없다. 솔랭 카드에서 응원 버튼을 눌러 이 판의 응원 수를 올리고, 팬들의 화력을 숫자로 보여준다. 솔랭 카드가 커뮤니티에서 반응을 얻었으니, 같은 자리에서 한 번 더 참여할 거리를 준다.

**이번 범위는 홈 솔랭 카드의 응원 버튼과 응원 수 숫자까지다.** 랭킹 화면, 월즈 경기 카드, 팀 응원은 데이터가 쌓인 뒤 따로 만든다(아래 "나중에").

## 사용자 흐름

1. 구독 선수가 솔랭 중이면 홈 솔랭 카드 하단에 이 판 응원 수와 `응원하기` 버튼이 붙어 있다.
2. `응원하기`를 한 번 누르면 이 판 응원 수와 내가 보탠 수(`+N`)가 1 올라간다. 누르고 있어도 연타되지 않는다.
3. 판이 끝나면 카드의 응원 영역은 사라지고, 끝난 경기 칩에 그 판의 응원 합계만 남는다.

## 화면 목록

| 화면 | 진입점 | 비고 |
|---|---|---|
| 홈 솔랭 카드의 응원 영역 | 구독 선수가 솔랭 중일 때 | 카드 하단에 이어 붙는다. 스와이프하는 카드마다 자기 선수의 응원 수와 버튼이 있다. 카드 높이는 기존 솔랭 카드(응원 영역만큼 늘어남)를 따른다 |

새 화면은 없다.

## 상태

| 화면 | 빈 상태 | 로딩 | 에러 |
|---|---|---|---|
| 응원 영역 | 솔랭 중인 선수가 없으면 카드 자체가 없어서 응원 영역도 없다 | 안 그림 | 안 그림. 전송이 실패해도 숫자는 먼저 올리고 나중에 맞출지 미결 |

## 필요한 API · 데이터

백엔드 코드를 `응원`·`cheer`로 찾았으나 이 기능과 관련된 것이 없다(검색에 걸린 것은 라이브 액티비티 푸시 등 무관한 코드). 응원은 전부 새로 만든다.

| 데이터 | 엔드포인트 | 있음 / 새로 / 확인 필요 |
|---|---|---|
| 선수 사진·팀·팀 로고 | `/api/players/cards`의 `playerImageUrl`·`teamCode`·`teamImageUrl` | 있음 |
| 구독 선수 목록 | 구독 API | 확인 필요 (홈 spec의 구독 선수 흐름을 따른다) |
| 솔랭 중 선수, 경과 시간, 챔피언 | 홈 솔랭 DTO | [홈 spec](../home/spec.md)에서 새로 만드는 솔랭 상태 필드(`gameStartTime`·챔피언)를 따른다 |
| 응원 전송 | 새 엔드포인트 | 새로. 선수 하나에 N번을 묶어 보낸다(아래 미결) |
| 선수별 이 판 응원 합계 | 홈 솔랭 DTO에 필드 추가 | 새로. 솔랭 폴링에 같이 실어 홈 응답을 늘리지 않는다 |

**저장은 처음부터 (사용자, 선수, 시각, 횟수) 단위로 한다.** 화면에는 선수별 합계만 보이지만, 선수 총합만 저장하면 나중에 팬 랭킹을 만들 수 없다.

## 결정

- 2026-10-09 (창하) **이번 범위는 솔랭 카드의 응원 버튼과 숫자만이다.** 랭킹·월즈 경기 카드·팀 응원은 데이터가 쌓이면 별도 페이지와 카드로 더한다. 범위가 작아야 빨리 내고, 실제 누르는 양을 본 뒤 랭킹 구조를 정할 수 있다. 빼 둔 설계는 아래 "나중에"와 [mockup-later.html](mockup-later.html)에 남긴다.
- 2026-10-09 (창하) **응원 영역은 솔랭 카드 하단에 이어 붙인다.** 솔랭 카드는 선수가 지금 뛸 때만 뜨고, 응원도 그때만 의미가 있다. 이미 반응을 얻은 자리라 새 섹션보다 첫 화면에서 잘 보인다. 사진 위에 반투명으로 얹는 안은 선수 사진 하단을 가려서 뺐다.
- 2026-10-09 (창하) **한 번 누르면 한 번 올라간다. 누르고 있어도 연타되지 않는다.** 꾹 눌러 연타하는 방식은 근거 없이 넣었던 것이라 뺐다. 숫자가 천천히 쌓여도 매번 눌렀다는 감각이 남는다. 어뷰징과 서버 쓰기 부담도 줄어든다.
- 2026-10-09 (창하) **버튼은 모서리가 둥근 사각형(높이 44px, 반경 10px)이다.** 토스 앱처럼 알약보다 모서리를 줄인 쪽이 단정하고 누르는 곳이 분명했다. 반경 14px·높이 52px 안은 어색해서 뺐다.
- 2026-10-09 (창하) **화력 게이지와 콤보는 없다.** 응원 수 숫자가 이미 화력이다. 빠르게 누르면 카드 테두리가 달아오르는 것만 남긴다.
- 2026-10-09 (창하) **내가 보탠 수는 큰 숫자 옆에 `+N`으로 작게 보인다.** `내`라는 글자는 붙이지 않는다. 가운뎃점, 알약 테두리는 어색해서 뺐다.

## 나중에

이번 범위에서 뺀 것이다. 설계 결정은 [mockup-later.html](mockup-later.html)(응원 랭킹 화면, 월즈 경기 카드, 팀 랭킹, 팬 랭킹의 팀 필터)에 그려 두었다. 다시 꺼낼 때 이 목록부터 본다.

- **응원 랭킹 별도 페이지.** 선수 랭킹 / 팀 랭킹 / 팬 랭킹 탭. 기간(오늘 / 이번 주 / 이번 달), 선수 필터 시트(내 구독 선수 / 전체 선수 / 팀), 팬 랭킹은 상위 100명까지 20명씩 `더 보기`, 내 순위는 하단에 고정. 팬 행을 누르면 그 팬이 응원한 선수 상위 5명을 시트로 보인다. 홈 카드 맨 아래에 `응원 랭킹 / 내 순위 N위` 줄로 진입하는 안이 있었다.
- **월즈 경기 카드.** 솔랭 카드와 같은 자리, 같은 스와이프. 응원 수가 팀마다 있고 점유율 바(분홍 / 보라)와 팀별 버튼 2개를 둔다. 한 팀 고정은 하지 않는다(랭킹은 누적 횟수라 양쪽을 눌러도 순위가 더 오르지 않고, 잘못 눌렀을 때 못 바꾸는 불만이 더 크다. 어뷰징이 보이면 그때 넣는다). 카드 위쪽을 누르면 기존 경기 상세로 가고, 아래 줄은 응원 랭킹으로 간다. 구독은 경기 단건으로도 할 수 있어서 `내 구독 팀`을 기준으로 삼지 않는다.
- **팀 응원 집계.** 팀 응원은 대회(월즈, LCK, MSI, LPL)별로 따로 세고 선수 응원과도 따로 센다. 기본 대회는 진행 중인 대회다. 대회 필터는 칩 하나와 시트이고, 응원한 팀만 거르는 필터와 행 강조·태그는 두지 않는다(목록 선택과 구별이 안 되고 화면이 도배된다).
- **팬 랭킹의 팀 정보.** 필터 시트에 `팀` 탭을 두고 팀과 대회를 고른다. 팬 응원 기록 시트에는 응원한 팀 섹션을 더한다.
- **후속 아이디어.** 솔랭 시작 푸시에서 바로 응원으로 들어오기, 경기 후 응원 결산 카드 공유, 누적 응원 돌파 알림, 응원 한마디 프리셋, 연속 응원 기록과 칭호.

## 미결

- **어뷰징 상한.** 계정당 초당 몇 번까지 받을지, 서버가 1초 단위로 묶어 합산할지. 매크로 부풀리기를 막고 DB 쓰기도 줄이려면 필요하다.
- **전송 실패.** 숫자를 먼저 올리고 나중에 서버 값에 맞출지, 실패하면 되돌릴지.
- **판이 끝난 뒤.** 끝난 경기 칩의 응원 합계는 그 판 합계인데, 칩을 눌렀을 때 어디로 가는지.
- **선수 한글 활동명.** 목업은 영문 이름(Faker)이다. 홈 spec의 한글 활동명 추가와 같이 정한다.
- **랭킹을 열 시점.** 응원 데이터가 얼마나 쌓이면 랭킹 페이지를 만들지, 그 전에 볼 지표(하루 누른 사용자 수, 사용자당 횟수).
- **나중에 항목의 미결.** 랭킹 갱신 주기, 기간 경계(KST 자정, 월요일 시작), 응원 대상 공개 설정, 구독하지 않은 선수의 응원 위치, 경기 상세 안의 응원, 경기 카드 응원 지속 범위(세트별 / 경기 전체), 양쪽 응원 어뷰징은 해당 기능을 만들 때 정한다.

- [mockup-later.html](mockup-later.html)의 랭킹 수치, 내 순위, 팬 닉네임, 월즈 대진(T1 vs GEN, HLE vs KT)과 스코어, 점유율도 전부 예시다. 팬 닉네임은 실유저가 아니다.
- 구독 27명, 솔랭 중 선수 2명, 끝난 경기 4명은 [홈 목업](../home/mockup.html)의 예시 상태를 따랐다.
- 하단 네비와 오늘 경기·순위표는 그리지 않았다. 홈 목업을 본다.
